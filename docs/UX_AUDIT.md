# Phase 2C experience audit

An engineering visual/interaction audit of the preserved Phase 2B app and Phase 2C refinements. It is not educator approval, a screen-reader audit or a learner study. Stitch was excluded at the user's request. Existing system typography, curriculum wording, chessboard, engine behavior and conservative coaching judgments were retained.

## Findings and changes

| Observed issue                                            | Refinement                                                                                              | Evidence / remaining limit                                                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Mobile navigation occupied several rows before the lesson | Compact approved symbol, current page cue, accessible expandable menu                                   | 320px menu, keyboard activation, Escape/return focus and 44px header controls tested                              |
| Light-only surrounding UI                                 | System/light/dark themes; deliberate light logo badge; unchanged readable board                         | Primary text token pairs pass 4.5:1 checks in both themes; not a full contrast/conformance audit                  |
| Review metadata and long preamble preceded the task       | Saved-game selector/PGN and scope explanation in native expandable sections                             | The original position, decision picker and question appear earlier; full game history/export remain available     |
| Original and candidate boards could be confused           | Explicit Original position / Candidate preview / Your retry labels                                      | Existing full recovery journey now checks labels and focus, without changing acceptance rules                     |
| Feedback below a phone board could be missed              | Focus the first prediction question and retry-feedback heading; return focus to original piece          | Keyboard and mobile recovery scenarios verify focus; physical assistive technology remains pending                |
| Partial baseline results visible through `/evaluation`    | Withhold metrics/export until all five baseline decisions finish and active independent checks are left | Reproduced against baseline; partial, active and answered-but-not-left checks now tested; timer remains available |
| No single repeatable pilot itinerary                      | `/pilot` links seven existing stages, explains consent, exposure and completion boundaries              | Counts show recorded activity only; no score/answer leakage or mastery assignment                                 |
| Narrow text/buttons and platform edges                    | Responsive spacing, wrapped button copy, safe-area padding, broader skip-link wording                   | All main routes fit 320/375/768/1440px in both themes with reduced motion                                         |

The outcome gate is a presentation safeguard, not access control over browser-local data. A participant with developer tools can inspect their own storage. Supervision and unused, reviewed assessment positions remain essential.

## Before/after evidence

`artifacts/phase2c/before-verified/` contains 24 Phase 2B states: lesson, learning home, baseline, guided practice, progress, active Play, populated Review and Local results at 320/375/1440px. `final-light/` and `final-dark/` contain the same 24 states per theme. The fixture uses synthetic resigned games and deliberate “not sure” baseline responses, never learner records.

- Progress/evaluation: matching `progress-*` and `evaluation-*` in each folder.

Opened representative final lesson, learning, gameplay, populated review, guided practice and progress images at narrow/wide widths and in both themes; the pilot screenshot is generated by its browser scenario. All 72 comparable before/final captures report no overflow, page exceptions, console errors or unexpected HTTP/request failures. Expected cancelled Next RSC prefetches are identified only by the exact `ERR_ABORTED` plus prefetch/RSC headers and reported separately.

Two initial capture-probe runs counted those normal prefetch cancellations as errors. The probe was corrected; raw earlier attempts remain local. Screenshot fixtures use a fixed date and their performance entries are unavailable. Do not use their null timings or zero resource counts as performance evidence. `scripts/measure-experience.mjs` measures separately without clock instrumentation.

## Educational boundaries and next observations

Thinking before reveal, graduated hints, independent answers, familiar retries and targeted practice remain distinct. No engine evaluation appears during independent play. The pilot itinerary does not bypass curriculum prerequisites or create held-out content. Long review explanations and progress logs still require scrolling; expandable sections trade immediate detail for earlier task visibility. Test discoverability with actual beginners before further shortening content.

Physical-device touch accuracy, screen readers, text zoom, home-screen behavior, battery/thermal use and educator comprehension review remain pending. Use the existing [mobile protocol](MOBILE_TEST_PROTOCOL.md), [pilot protocol](BEGINNER_PILOT_PROTOCOL.md) and [release checklist](PILOT_RELEASE_CHECKLIST.md). The next milestone is educator/device review followed by the prepared formative pilot, not more feature expansion.
