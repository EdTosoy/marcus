# User journeys and cognitive walkthrough

This is an **analyst simulation**, supported by actual browser interactions and source inspection. “Clear,” “mixed” and “break” are judgments about discoverability and feedback, not measured responses from participants. The four questions at each meaningful step are: does the goal make sense, is the action findable, is its result understandable, and is continuation clear?

The audit uses isolated browser contexts, synthetic history and the current Marcus build at port 3463. No existing user data was changed. Evidence links are before any proposed design work. See [the method and limits](DESIGN_AUDIT.md).

## Persona A: complete chess beginner

**Intent:** understand how to begin learning and make a first informed decision.

**Assumption to challenge:** the app says “Beginner foundations,” while the pilot protocol requires knowledge of basic legal moves. It currently teaches positional safety rather than a complete introduction to chess rules. A complete rules beginner may not recognize pieces or coordinate notation. That comprehension risk was simulated, not tested with a learner.

## Persona B: returning learner

**Intent:** resume useful practice, understand what has been learned and respond to a due review.

**Repository limit:** there is one guided lesson, not several separate lessons. The synthetic returning profile contains that completed lesson plus five diagnostic and four guided/transfer exercise records. Dates are fixture dates, not learner outcomes or an actual elapsed follow-up study.

## Loading, failure, empty and special-state walkthrough

| State                                       | Actual observation                                                                                                        | Design consequence                                                                                                                                 |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Application JavaScript deliberately delayed | Server-rendered “Restoring local practice…” remains understandable                                                        | A labeled loading state is useful; a decorative skeleton is not automatically required                                                             |
| Empty Review / no completed games           | Honest empty state with Play link; no fabricated coaching                                                                 | Preserve recovery, reconsider whether this needs a peer global destination before a game exists                                                    |
| Worker download deliberately failed         | Alert, error heading and Restart engine exist; ordinary wait instruction remains                                          | Distinguish intervention from waiting; D15                                                                                                         |
| Storage deliberately denied                 | A visible warning permits in-memory work                                                                                  | Preserve; avoid promising persistence when storage is unavailable                                                                                  |
| Promotion by keyboard at 320px              | Explicit queen/rook/bishop/knight/cancel controls are available, at least 48px high; chosen knight produced terminal draw | Preserve underpromotion and cancel behavior. Focus stays on the destination until the user advances; actual AT announcements still require testing |
| Navigation and skip link                    | Menu opens by keyboard, Escape returns focus, skip link reaches main                                                      | Preserve these working alternatives                                                                                                                |
| Reduced motion                              | Captures use reduce; board animation is disabled and global rules suppress animation/transitions                          | No essential task depended on motion in the inspected flows; do not add animation as a substitute for state clarity                                |

## Questions for the first real sessions

Observe rather than suggest the answer: Where do learners go after completion? Do they find an offscreen response? What board do they think an engine candidate refers to? Can a keyboard learner reach the board without assistance? Do they distinguish repeating a known board from unfamiliar success? How often is the first selection accidental? Can they explain an attack after a hint, without quoting the hint?

Use educator-approved unused boards for learning comparisons, not these screenshots. Keep task completion, assistance, confusion, independent response and delayed unfamiliar performance in separate records. This audit supplies no participant findings or effectiveness estimate.
