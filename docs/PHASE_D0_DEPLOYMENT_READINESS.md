## Application and hosting suitability

Installed and pinned versions are Next.js 16.4.3, React/React DOM 19.3.1, Stockfish 19.0.1, TypeScript 5.9.3 and pnpm 11.27.0. `pnpm-lock.yaml` uses lockfile version 9. The isolated frozen install succeeded with 388 cached packages, no downloads and lifecycle scripts disabled; its lockfile remained byte-identical. Corepack selects the package-manager pin explicitly. Node 24 is supported by Vercel. [Node versions](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions), [package managers](https://vercel.com/docs/package-managers)

The production route table is:

| Rendering                 | Routes                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------- |
| Prerendered/static        | `/`, `/board`, `/evaluation`, `/pilot`, `/play`, `/manifest.webmanifest`, not-found page |
| Server-rendered on demand | `/learn`, `/review`                                                                      |

`src/app/learn/page.tsx` and `src/app/review/page.tsx` await request `searchParams`, accounting for the server rendering. There are no API route handlers, Server Actions, middleware, database clients, server filesystem persistence, cron jobs or remote model services in the application. This is a Next.js deployment with two dynamic routes; a static-export conversion would require application changes and is unnecessary for D0.

Stockfish runs in a browser Web Worker. It uses a single thread, bounded searches, no pondering and lazy initialization. Server CPU does not run chess searches. Browser-local learning/game/timing/theme records persist in `localStorage`, with visible recovery behavior when storage is unavailable. Progress is tied to the browser and origin, is user-editable, and has no server backup or synchronization. PGN/JSON exports are local downloads. No app authentication or runtime credentials are needed. Keep participant exports and browser storage out of shared artifacts and logs.

The isolated build contains 2,199,916 bytes in `public` and 1,263,841 bytes under `.next/static`, about 3.46 MB combined before compression, HTML and RSC responses. The largest public file is the 1,845,971-byte WASM; its worker JS is 28,230 bytes. One thousand initial WASM downloads alone would transfer about 1.85 GB before compression/caching. These are file-size estimates, not measured production traffic or an allowance guarantee. Engine assets are generated during the build; a successful bare Next build would not establish their presence.

Hobby is a plausible low-cost host for a small **personal, non-commercial** pilot if that accurately describes the intended use. Its documented included allowances include 100 GB fast data transfer, 10 GB origin transfer, one million CDN requests, one million function invocations, 4 CPU-hours and 360 GB-hours of provisioned function memory. Allowances are shared with other team projects. This audit did not measure current team consumption. Exceeding Hobby limits generally pauses the feature rather than buying overage. Commercial or institutional use needs a plan eligibility decision; a paid plan introduces subscription and usage charges. No paid add-on, database, analytics, monitoring integration or custom domain was provisioned. [Hobby plan and restrictions](https://vercel.com/docs/plans/hobby)
